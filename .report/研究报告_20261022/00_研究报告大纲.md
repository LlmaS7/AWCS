## 一、报告定位与研究主线

围绕“如何将人员表达的搬运需求转化为满足业务约束、可校验执行、可追踪结果的多机器人协同任务”展开。采用问题提出、方法选择、系统实现、实验验证、局限讨论的论证顺序。

材料范围仅限 E:/_PROJECTS/AWCS 内的源码、README、.report、.temp 中相关测试证据，以及可核验的公开一手资料。不引用 SDITADC 旧项目，不读取密钥，不新增模型或算法测试。

现有结论统一以 ../test_res/测试结论.md 为入口；原始批次、修复专项及追加规模实验分别陈述，不能合并分母或用补跑替换首次结果。

## 二、拟定目录与写作重点

### 摘要与关键词

交代问题、方案、主要实验结果和适用边界；摘要同时保留常规场景完成情况与大规模、Agent 全量验收的限制。

### 第 1 章 研究背景与目标（正文约 10%）

1.1 现有系统情况：人工/表单操作、WMS 业务管理、机器人车队调度、MAPF 研究工具各自的作用；使用官方系统资料说明已有订单、机器人和状态集成能力，不把行业描述为尚无自动化。

1.2 本项目面对的不足与需求：非结构化临时指令与结构化任务之间需要转换；任务分配需要尊重紧急程度及执行阶段；空间冲突需要时间协调；交互和算法需要形成可观察的执行闭环。区分一般工程分析与本项目实测证据，不虚构仓库访谈和生产降本数据。

1.3 设计目标与研究问题：业务语义接入、约束一致的分配、安全路径协调、可复核验证。明确教学、竞赛与仿真研究定位。

1.4 范围：静态四邻域网格、单格机器人、简化装卸；不含实体机器人控制、库存、载重、电池、长期生产运行。

### 第 2 章 相关方法与问题建模（约 13%）

2.1 整体匹配、SIPP、CBS、持续任务与滚动协调、工具调用智能体的研究背景。

2.2 图模型、机器人、取送任务、任务阶段及时间单位。

2.3 硬约束、分层目标及碰撞定义；区分任务分配子问题与完整系统的最优性。

2.4 方法选择及适用边界；说明算法来源与项目适配，避免把已有算法作为原创成果。

### 第 3 章 系统总体方案（约 14%）

3.1 交互、业务智能、状态控制、独立规划进程、仿真执行和记录层。

3.2 用一项任务串联需求、创建、匹配、规划、提交、执行及查询。

3.3 版本核对、状态一致性与边界检查。

3.4 地图工坊、同步 3D/2D、指标与回放的研究支撑作用。

### 第 4 章 核心方法与实现（约 29%）

4.1 分层优先级与匈牙利匹配：动态权重、虚拟空分配、人工指定、软偏好、静态 ETA。

4.2 分阶段分配与紧急插单：装货前可抢占、装卸连续、载货交付优先完成。

4.3 SIPP 与时空预约：安全区间、顶点冲突、对向换位、停车持续占用；规划顺序尝试和局部 CBS 修复。

4.4 预算与有限候选联动：共用预算、保留优先级前缀，仅比较实际可行候选。

4.5 独立校验与失败恢复：版本匹配、任务/路线一致、已有完整路线有限续行条件；说明实现与历史测试的版本差异。

4.6 Agent 与文档任务导入：查询、工具调用、执行回执、来源草稿、人工确认；D07 取消对象来源保护。

### 第 5 章 实验设计与评价方法（约 12%）

5.1 证据批次、测试环境、版本和预算。

5.2 核心正确性检查、4/16 台主场景、32 台规模、动态流、64 台追加实验。

5.3 Agent 原主矩阵、未运行范围、语义复核与 D07 新专项。

5.4 指标和计分单位；安全、完成、模型业务正确、后端保护分别评价。

5.5 可复现条件与有效性限制；不将当前未执行的对照实验写为结果。

### 第 6 章 结果与讨论（约 18%）

6.1 1,715 项核心检查与 25 项回归；轨迹复审范围。

6.2 主场景 28/28、32 台 5/8、动态流 1/3；披露五项未完成的实际完成任务数。

6.3 64 台：19 次策略试验、六个冻结现场、两张图从头证据及测试侧复用条件。

6.4 Agent：原矩阵 146 PASS、10 FAIL、1 INCONCLUSIVE、23 NOT_RUN；A/B 常规能力；状态表述与文档约束归类问题。

6.5 D07：历史越权反例、程序修复、真实模型主动澄清与离线强制错误调用拦截分别解释。

6.6 讨论：交互正确不等于执行完成，安全停止不等于无解，小样本修复不等于全量验收；提出需进一步验证的原因假设。

### 第 7 章 结论与展望（约 4%）

逐项回答研究问题，归纳业务与调度连接、约束处理和可复核平台贡献；优先安排 Agent 余项复测、预算与密度控制实验、恢复机制回归，实体部署作为后续方向。
