# AWCS 演示视频脚本

编制日期：2026-10-22。依据当前源码、README、统一测试结论及本次提供的评分图编写。**成片目标约 7 分钟，建议控制在 7 分 30 秒以内，硬上限 8 分钟。**

本文件中，“操作”是录制说明，“讲解词”可直接朗读；编号占位符须替换成画面中的实际编号。各段只给大致篇幅，不要求按秒卡点。配套的 `02_录制速查表.md` 适合录制时放在另一块屏幕上。

## 一、视频应让评审看到什么

评分图中，“视频展示质量”占 15 分，强调内容完整、逻辑清晰，以及项目功能、技术亮点、实际效果和画面讲解质量；“项目实物/系统展示效果”占 10 分，强调完整演示、友好界面、流畅交互和直观证据。因此采用这条主线：

**提出搬运需求 → 任务实际创建 → 机器人分配与协调通行 → 搬运完成 → 核对状态与指标。**

技术部分围绕“如何理解需求、如何分配、如何避让”解释设计，再用文档导入、地图工坊和历史测试补足功能与验证。应用价值落到仿真验证、布局实验和教学，避免虚构生产部署成效。

| 段落 | 内容与主要画面 | 建议篇幅 |
| --- | --- | --- |
| 1 | 运行总览与项目定位 | 约 25 秒 |
| 2 | 自然语言下单，追踪一项任务完成 | 约 75 秒 |
| 3 | 优先级调整与紧急插单 | 约 45 秒 |
| 4 | 三项技术亮点，配两处关键源码 | 约 80 秒 |
| 5 | 文件拖入、任务草稿与人工确认 | 约 60 秒 |
| 6 | 地图工坊与布局扩展 | 约 40 秒 |
| 7 | 运行指标与已有测试证据 | 约 50 秒 |
| 8 | 应用价值与当前范围 | 约 20 秒 |

上述段落约 6 分 35 秒，另留约 25～50 秒给操作停顿、转场和片头片尾。实际长度以一次完整试读和剪辑时间线为准。

## 二、录制前准备

1. 推荐使用 **`fleet_64x64` 地图、16 台机器人、固定种子 `20261010`**。地图名称可能含“32台”，这是登记容量；画面和解说都应以实际运行的 16 台为准。
2. 在项目根目录启动：

   ```powershell
   .\.venv\Scripts\python.exe main.py --map fleet_64x64 --robots 16 --seed 20261010 --planner scalable_full --coupling off --plan-seconds 3 --paused --debug-window --no-save
   ```

   `--no-save` 用于避免退出时自动覆盖已有运行记录；第七段手动“保存记录”仍会写入 `outputs/last_run.json` 和 `outputs/last_scenario.json`，需要保留旧记录时先自行备份。

3. 提前配置并测试 AI，不把配置过程录进正片。API Key、私人配置和聊天窗口不要出现在录屏范围。
4. 确认主窗口、调试窗口均连接正常，自动生成保持关闭，仿真保持暂停。**启动场景已有 9 项初始任务**，先记下画面中的实际任务数，后续以增量判断创建效果。
5. 先在 AI 助手查询可用地点，确认 `P01`、`P02`、`P03`、`D1`、`D2` 都存在；若换图，以真实地点表为准同步修改话术和演示搬运单。
6. 编辑器提前打开 `coordination/assignment.py` 的 `match` 和 `planning/reservations.py` 的 `Reservations.add_path`。隐藏终端，放大字号，每屏只露关键代码。
7. 提前打开 `.report/AWCS_测试报告.html`，定位主场景结果和 D07 专项；打开地图工坊，排练一次生成与检查。录制时不安装依赖、不现场找文件。
8. 建议分段录屏后配音。保留真实输入、回执和最终状态；删去纯等待时，可加“已省略模型等待”字幕，仿真倍速或后期加速要标注。不要把不同运行的编号和指标接成同一场景。

## 三、正式脚本

### 第一段：开场就展示系统

**操作与画面**

- 片头简短显示“AWCS · 智能仓储协同调度系统”和团队信息，接着进入真实运行画面。
- 用预先录下的一小段多机器人运动画面开场；轻微旋转 3D 视角，随后恢复视角，让 2D 地图和任务中心也能看清。
- 正式操作段切回上述暂停初始现场。开场镜头可加“系统运行概览”字幕，避免让人误以为前后状态连续。

**讲解词**

> 大家好，我们的项目是 基于AI-agent的智能仓储协同调度系统。它面向仓库搬运场景，把自然语言的ai助手、任务分配、多机器人路径规划和可视化仿真整合在一起。下面将通过一系列搬运任务，展示系统从接收需求到执行完成的全过程。

### 第二段：用一句话下单，并看到任务完成

**操作与画面**

1. 主窗口切到“AI 助手”，发送：

   ```text
   请查询当前可用的取货点和配送点，并简要说明当前任务情况。
   ```

2. 保留查询结果中的地点和状态画面，再发送：

   ```text
   新建一项搬运任务：从一号货架取货，送到1号配送点，优先级2级。
   ```

3. 等待出现实际创建回执，记录新编号为 **〈主线任务编号〉**，例如 T010；后文所有编号都替换成该次真实结果。点击回执中的任务编号，切到“任务列表”，展示取送位置、等级和执行者。
4. 点击“继续”（暂停按钮会随状态改变文字），先以 2× 展示，再按需要切 4×。追踪取货、装货、配送、卸货和完成；重点保留载货小箱子出现、任务状态变化和完成结果三个镜头。中间长路程可省略并标注。
5. 暂停后回到助手，发送 `查询〈主线任务编号〉的当前状态。`，将助手返回的真实状态与任务列表相互核对。

**讲解词**

> 左侧的三维仓库与二维地图展示同一组机器人，右侧是任务中心和业务助手。
在开始使用前，需要先进行AI的配置。配置好后可以测试连接情况。
接下来，我们可以先查询已有任务，再用一句话创建搬运任务。
>
> 现在可以看到创建信息，任务列表中也自动更新了有关内容。这说明需求已经进入实际调度中。追踪任务，可以查看取货点和配送点，并跟踪执行机器人。
>
> 继续运行后，机器人前往取货点，完成装货，再前往配送点卸货。机器人上方的小货箱表示载货状态。二维视图可以放大观察通行路线，三维视图则呈现搬运过程。
>
> 这项任务现在已经完成。我们再查询同一个编号，核对助手回答与任务中心的实际状态，由此形成从下单到执行结果的完整闭环。

**本段必须留下的证据**：创建回执、同编号任务详情、载货执行画面、完成状态。若任务尚未完成，继续录制直到完成，不能只用创建成功代替搬运成功。

### 补充口播：Agent 还能做什么（约 40～50 秒）

接在第二段的基本 Agent 演示后即可。可以沿用 AI 助手和任务列表画面，不必逐项补录操作；如果后面已有文件导入演示，最后一句可以省略。

> 除了刚才演示的下单和查询，Agent 还可以应对临时调整。比如，把任务设为紧急、取消尚未装货的任务，或者指定执行机器人。
>
> 也可以告诉它：“优先让三号机器人来做，忙的话就安排其他机器人。”这样既能表达我们的偏好，也给系统留出灵活安排的空间。对于尚未装货的任务，还可以解除指定，恢复自动分配。
>
> 遇到重复的搬运需求，可以直接复制已有任务；想了解整体运行情况，也能查询完成数量、移动距离和等待情况。另外，还支持从文件清单中整理搬运需求，核对确认后批量创建任务。

### 第三段：紧急插单与业务约束

**操作与画面**

1. 在调试窗口点击“自定义任务”，选 `P02 → D2`，等级 2，创建一项任务。记下 **〈插单任务编号〉**。在仿真暂停、尚未装货时，回主窗口选中它，点击“设为紧急”，展示等级变为 5。
2. 继续运行，展示任务分配和路线更新。若当前有空闲机器人，它可能直接接手紧急任务，这是正常情况。
3. 选中一项已经载货的任务，展示其阶段，以及“取消任务”等操作的界面状态；无需真的取消。
4. 若希望额外展示“紧急抢占”，须单独排练并录到真实抢占计数变化。主脚本不依赖这一镜头，避免为了抢占临时堆积大量任务。

**讲解词**
> 为方便调试，我们也准备了对应的调试窗口。

> 仓库任务可能临时变更。这里将一项尚等待分配的普通任务提升为紧急任务，系统会按新的紧急程度重新安排。



**画面解释**：仅在看到真实归属变化或“紧急抢占”计数增加时，才补充“这里发生了一次抢占”。等级变红、规划更新或空闲机器人接单，本身不足以证明抢占。

### 第四段：解释三项技术亮点

**操作与画面**

- 先用一张简洁字幕卡列出“业务工具调用 / 分层匹配 / 时间协调与校验”。
- 第一屏源码：打开 `coordination/assignment.py` 的 `match`，突出 `value[5-task.priority]`、`value[-2:]`、动态 `weights` 和 `minimum_assignment`。可以分两次裁切显示，不要把整文件缩成小字。
- 第二屏源码：打开 `planning/reservations.py` 的 `add_path`，突出 `self.block`、`self.block_edge`、`persistent`。随后切回放大的 2D 运行画面，显示多台机器人共用通道。
- 源码总停留约 20～30 秒，其余讲解配运行画面；无需现场逐行读代码。

**讲解词**

> 系统的技术设计主要体现在三个方面。
>
> 第一，业务助手通过工具读取状态、提交操作，再根据程序回执回答。语言模型负责理解需求，任务分配与路线计算交给确定性的算法模块。取消任务时，程序还会核对本轮明确给出的编号或界面关联对象，防止查询结果被擅自当成取消目标。
>
> 第二，任务分配采用分层目标。先考虑各等级任务的分配数量，再比较机器人软偏好和预计完成代价，最后通过匈牙利算法做整体匹配。这里的权重由目标范围计算，避免距离优势覆盖高等级任务。
>
> 第三，路径规划同时考虑位置和时间。预约表记录某个格子何时被占用，并限制同一步的对向换位；SIPP 在可用的安全时间区间中搜索。必要时调整规划顺序，或用局部 CBS 修复冲突。
>
> 规划在独立进程中执行，结果提交前还要检查状态版本与整组路线。如果预算内没有形成可执行方案，系统会暂停并保留任务。这些设计把业务约束、协同规划和执行检查连接起来。

**字幕建议**

| 配套画面 | 字幕 |
| --- | --- |
| 助手回执与任务中心 | 理解需求 → 工具操作 → 真实回执 |
| 分配源码 | 等级优先 → 偏好与代价 → 整体匹配 |
| 预约源码与二维运行 | 格子占用 + 对向换位约束 + 安全区间 |
| 仿真继续运行 | 独立规划进程 · 版本核对 · 路线校验 |

**表述边界**：匈牙利算法、SIPP 和 CBS 均有既有研究来源。技术贡献讲本项目的业务建模、算法组合、约束衔接与工程实现；不说“原创匈牙利算法”“完整系统全局最优”或“任意任务流永不死锁”。

### 第五段：从文档提取任务，人工确认后执行

**操作与画面**

1. 暂停仿真，记下创建前的任务数。切到“AI 助手”，将本目录的 **`03_演示搬运单.md`** 拖到聊天区域。
2. 附件被读取后，在说明框输入：

   ```text
   提取本次待执行搬运需求，保留原文中的取送地点、优先级和搬运次数。
   ```

3. 点击“分析文件”，等待完成，点击“查看任务草稿”。展示三条需求、取送地点、等级、次数以及原文依据。
4. 明确停顿一下，指出此时仅有草稿，任务数尚未增加。检查内容正确后，点击“选择全部就绪项”与“确认创建”。
5. 展示逐项创建回执，并回任务列表核对 **新增 4 项**。第二条需求为 2 次搬运，因此三条需求展开成四项任务。
6. 如需展示 DOCX，可改用 `.temp/files/10_Word表格搬运清单.docx`；先在当前地图排练。正片选 MD 或 DOCX 的一份即可，不重复录完整流程。

**讲解词**

> 除了逐条下单，系统也支持从 Markdown、文本和 Word 文档提取搬运需求。这里把一份清单拖入助手，生成可以核对的任务草稿。
>
> 草稿保留取送地点、等级、搬运次数和原文依据。分析结束时还没有创建任务，需要人工核对并明确确认。这份清单有三条需求，其中一条需要搬运两次，因此确认后实际新增四项任务。
>
> 这样既能减少重复录入，也保留了从原文到实际任务的核对环节。

**预期与核对**：三条候选分别是 `P01→D1 / 2级 / 1次`、`P02→D2 / 5级 / 2次`、`P03→D1 / 3级 / 1次`。这是演示输入的预期，录制时仍须检查真实草稿和回执。若提取有误，应如实编辑核对后再提交，不能将错误结果配成成功讲解。

### 第六段：地图工坊，扩展场景

**操作与画面**

1. 打开调试窗口的“地图工坊 ↗”，选择 L 形轮廓，宽高 64×64、容量 16、种子 `20261018`。其他参数采用排练时已记录的值。
2. 点击“生成并预览”，展示轮廓、货架、通道和业务点；点击“检查地图”，展示实际检查结果。
3. “规划试运行”可提前单独录制，保留参数、完成数与检查结果；成功才使用对应画面。如时间不足，正片展示生成和静态检查即可，不必讲成已经试运行成功。
4. 保存、导出和切换新地图可以用简短补充镜头。**先保存主场景指标再切图**，否则“应用并重置”会清空任务。主线无需现场切换。

**讲解词**

> 为了验证不同布局，我们还提供独立地图工坊，可以设置轮廓、尺寸、机器人容量和随机种子，生成货架、通道及业务点，并进行格式与连通性检查。生成的地图可以保存、试运行，再导出到仿真中，用于比较不同仓库布局。

**可选补充句，仅在有真实试运行镜头时使用**：

> 这里还可以查看这一地图快照和任务批次的试运行结果。检查通过与试运行完成分别呈现，结果对应当前样本。

### 第七段：用执行指标和测试结果支撑效果

**操作与画面**

1. 回到原来的 16 台仿真现场，展示顶部“已完成”数量与调试窗口的“规划与执行指标”。重点指向完成任务、总移动距离、避让等待、平均完成时间和最近规划耗时。
2. 需要保存本次演示时点击“保存记录”，注意这会覆盖固定名称的已有运行记录。字幕使用这次画面的实际数值，不预填预计值。
3. 切到 `.report/AWCS_测试报告.html`，或据统一结论制作下面的简洁成绩卡。加醒目标题“已有测试批次”，与“本次演示运行”区分。

**讲解词**

> 运行效果可以通过已完成任务、移动距离、避让等待、平均完成时间和规划耗时来观察，记录也可以保存用于复盘。
>
> 已有测试中，一千七百一十五项核心检查通过；在十四张生成地图上，四台和十六台机器人的二十八个主场景全部完成。三十二台规模场景完成五组，共八组；有限动态任务流完成一组，共三组，其余用例在预算内安全停止。
>
> 业务助手已验证常规操作，针对模糊取消的问题完成了修补和三轮真实模型定向复测。更大规模、持续任务流和助手完整验收仍需继续完善。

**建议成绩卡，数字直接采用统一测试结论**

| 已有验证项目 | 结果 |
| --- | --- |
| 核心检查 | 1,715 项通过 |
| 4/16 台主场景 | 28/28 完成，覆盖 14 张生成地图 |
| 32 台规模场景 | 5/8 完成，其余预算内安全停止 |
| 16 台有限动态任务流 | 1/3 完成，其余预算内安全停止 |
| D07 取消目标专项 | 模糊指代澄清、明确编号取消、关联对象取消各 3/3 |

成绩卡底部加小字：“不同测试批次与统计单位分别报告；D07 为专项复测，Agent 尚未完成新版本全量验收。”

**录制者须知**：1,715 为检查项，28 为完整场景，不能相加计算总通过率。D07 真实模型主动澄清，不能讲成三次均被后端拦截。不要把 64 台追加实验写成默认能力，也不要添加未经对照测试的吞吐提升或成本下降百分比。

### 第八段：回到价值，简短收尾

**操作与画面**

- 回到运行总览，保留机器人运动与已完成任务。
- 结尾字幕：“自然语言业务接入 / 多机器人协同 / 可观察、可复核的仿真验证”。

**讲解词**

> AWCS 将人员表达的需求、调度决策和执行结果连接起来，可用于仓储调度方案验证、布局实验和相关教学。当前实现采用静态网格与简化装卸仿真，后续将完善复杂任务流，并探索实体机器人接口。以上就是我们的项目展示，谢谢。

## 四、剪辑与超时处理

- 优先保留“创建—执行—完成”的同编号证据，确保评审能看懂真实效果。助手纯等待、长距离行驶和窗口寻找可以压缩。
- 成片超过 7 分 30 秒时，先删除地图保存与切换补充镜头，再缩短状态查询和源码停留；技术部分保留三个设计及其依据，避免只剩功能菜单。
- 再次超时时，地图工坊仅留生成与检查两镜头。测试成绩卡保持可读，不快速滚动整份报告。
- 可将 4× 仿真与后期加速分别标注；字幕、片头片尾都计入 8 分钟。
- 1080p 录屏、清楚的人声、可读的字号即可。最终检查声音、字幕、实际编号、画面指标与讲解一致，避免背景音乐盖过人声。
