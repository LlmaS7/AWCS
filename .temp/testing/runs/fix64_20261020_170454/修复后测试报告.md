# AWCS 安全路线复用修复及回归测试结论

日期：2026-10-20（香港）；批次：`fix64_20261020_170454`。

**修复已接入正式程序：完整模式重规划失败时，重新验证当前全部剩余路线；验证通过才限步继续执行。直接仿真和异步控制器使用相同的状态所有者校验。**

64 台从头测试：原 8 秒规划预算 **2/6** 完成；10 秒对照 **2/6** 完成。所有未完成记录保留，不能将不同预算合并声称默认配置全部通过。

## 1. 实现与边界

- coordination/recovery.py：检查当前完整路线的障碍、合法移动、同格/对向换位、完整装卸、任务覆盖和持久停车；确认确有后续移动或服务可推进。
- simulation.py：失败候选绝不提交；可复用时保留已提交任务、归属、载货和路线，授予 32 步执行区间。期间任务状态变化须重新校验，校验不延长原区间；到期重新尝试规划。
- controller.py：异步控制器对有效复用区间执行同样的复查；原有请求标识、场景代际、时刻与过期结果淘汰逻辑保留。人工暂停状态保留。
- 恢复仅适用于 scalable_full，且没有 pending 任务、所有未结束任务均已被当前/预留槽覆盖。新增待分配任务会结束复用并重新规划；取消或改派后须按新状态验证。
- rolling 模式不从此机制获得新证书；legacy_full 失败保护保持原样。取消搜索、规划进程异常、路线验证失败均不能启用恢复。
- 新增 tests/test_plan_recovery.py，可用项目虚拟环境运行 python -B -m unittest discover -s tests -v。

## 5. 可用于提交的结论

> AWCS 已接入完整模式下的安全剩余路线复用，并通过 25 项针对性回归及 1,715 项核心检查。四个原 64 台停滞现场均通过真实控制器与规划子进程恢复至 128/128；从初始状态测试时，8 秒和 10 秒预算均完成 2/6，仍有早期搜索未完成项。4/16 台主集完成 28/28，32 台本轮完成 5/8，有限动态流完成 1/3；未完成项与修复前对照单独披露。已审计的方案和实际轨迹未发现冲突或装卸约束违规。本轮未达到所有配置通过，64 台及预算敏感场景仍按实验范围交付，不保证任意任务流下全局最优或长期无死锁。

## 7. 最终收尾版本

大矩阵及轨迹审计完成后，修正了正常规划成功时仍显示路线复用提示的问题，并清理直接从恢复模式切到 legacy_full 后残留的执行期限，防止到期后每步重复规划。另增三项回归：成功状态更新、直接旧模式运行超过原期限、真实控制器切换模式并保持人工暂停。最终持久测试为 25/25，通过日志见 cleanup_unittest.stderr.txt。

64 台、原规模和核心大矩阵数据对应 source_hashes_after_fix.json / source_snapshot/；最终代码对应 source_hashes_cleanup.json / source_snapshot_final/。收尾没有改变完整模式路线复用、任务匹配、路径搜索、异步控制器或独立安全校验算法；不将大矩阵的冻结版本与最终文件指纹混为同一份文件。cleanup_integrity.json 记录两版本差异。此前的大矩阵和轨迹不重复累计，原始结果保持不动。
